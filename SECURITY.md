# Security

## Exposed surface

The API binds to loopback. Remote access is intended through Tailscale Serve HTTPS, with a separate Workspace token even inside the tailnet. The browser uses an HttpOnly, SameSite=Strict cookie (Secure on HTTPS). The server checks Host and Origin, limits login attempts and request size, applies CSP, and authenticates screenshot access. A worker has its own token and must present the current project-qualified lease nonce. A single owner token currently reaches every configured project; project-specific human roles are not implemented.

The browser cannot register repositories or arbitrary test commands. Repositories and checks come from local `projects.json`. Tasks run in separate Git worktrees and never merge, push or deploy automatically. Worktrees share Git object metadata with their source repository; they are not an OS sandbox. Protected-path changes produce `UNVERIFIED` instead of approval.

## Process boundaries and tested results

Claude Code runs with the official `--restricted` and `--strict-mcp-config` modes, without Bash, PowerShell, code execution or WebFetch tools. A real Claude CLI probe denied both a Read and an Edit of a controlled file outside its worktree (`npm run test:provider-boundary`). This confines its built-in file tools; the Claude process still holds its subscription authentication and other resources available to its OS account.

Windows Codex CLI 0.164.0 still fails before loading AGENTS.md when an actual `codex exec` uses the custom MXC profile: the child environment lacks `SYSTEMROOT`. The Windows provider now requires WSL2 Ubuntu and the audited Linux Codex 0.164.0 profile with root deny, a scoped Worktree mount, explicit secret-file denies, and no network. It does not fall back to broad-read `workspace-write`. `npm run test:codex-boundary` observed six operations in a real Codex AI session: allowed Worktree read/write succeeded; outside Workspace data read/write and installed-dependency/cache writes failed. The outside canary did not appear in output. Each run performs deny probes before execution. The Workspace creates empty mount target directories before launching Codex so synthetic sandbox placeholders cannot appear in the reviewable diff; a conflicting file or symlink blocks execution. WSL is part of the trusted host; this confines the Linux subprocess but is not a separate VM security boundary against an administrator or kernel attack.

Windows Node and Expo verification commands now run in WSL through the same root-deny filesystem profile, under an independently bounded systemd scope. `npm run test:sandbox-check` passed the sample syntax and test commands; `npm run test:wsl-check-boundary` read an allowed file and denied a Workspace data canary. A direct strict-profile run of Momentory FE typecheck and lint passed; the full Jest run is recorded separately in `TEST_REPORT.md`. Linux dependencies are installed with configured `npm ci --ignore-scripts` before checks, without executing package lifecycle scripts. The dependency setup profile has network access only while fetching reviewed packages; its filesystem boundary probe denied an outside read and persistent write.

Spring checks now route to WSL instead of the broader-read Windows MXC check profile. The trusted, committed Gradle build first resolves dependencies in a root-deny setup scope. Subsequent Gradle tests use `--offline` inside a nested user/network namespace with loopback enabled and external egress absent; `test:wsl-loopback` observed a successful local connection and denied external connection. OpenJDK 21 and Gradle run under memory, CPU, wall-time and 384-task limits. A cached Byte Buddy agent is loaded at JVM startup so Mockito tests do not need runtime self-attach. `test:be-isolation` passed the full configured Momentory BE suite with `BUILD SUCCESSFUL`; Docker-dependent cases may be skipped when Docker is unavailable.

Provider and check subprocesses do not inherit Workspace tokens or environment variables whose names indicate keys, secrets, passwords, credentials or authentication. Log redaction covers common token forms and exact secret environment values, but is not a complete data loss prevention control. Windows WSL Codex and Node/Expo checks run under systemd memory, swap, task-count and CPU quotas plus CPU and wall-time limits. The resource test observed a 256 MiB memory cgroup and two-second CPU limit killing controlled fixtures; a real Codex session was cancelled and another hit its wall timeout. Worker restart reaped a dead-owner WSL scope. A partial Worktree diff remained `STALE`, required its reviewed hash before resume, and resumed without a duplicate claim. macOS sandbox behavior has not been tested on a Mac.

## Release limitation

The MXC failure is bypassed only through the verified WSL backend; a missing or changed WSL boundary blocks Windows Codex jobs. Project-specific human roles are not implemented. Physical Tailscale phone access, locked-screen operation, macOS isolation, and native app screens remain unverified. Do not use this build with unknown users or highly sensitive repositories. Tailscale Serve and a phone on another network have not been tested because Tailscale is not installed on the available laptop. No local development port is intentionally exposed to the public internet.
