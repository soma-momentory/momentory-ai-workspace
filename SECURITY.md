# Security

The API is restricted to `127.0.0.1` or `::1`; remote access is intended through authenticated Tailscale Serve HTTPS. A separate Workspace token is required even inside the tailnet. The local worker uses a different bearer token. The browser receives an HttpOnly, SameSite=Strict session cookie, with Secure on the HTTPS origin. Requests require an allowlisted Host; state-changing browser requests require an exact configured Origin. Login attempts are rate limited. CSP, request-size bounds, server-side authorization, and authenticated screenshot access are present.

Projects are configured locally in `projects.json`; remote users cannot register a filesystem path or validation command. Git roots are verified before worktree creation. Tasks are stored under project IDs and run in project/task worktrees; workers must advertise a project-qualified repository capability. A single owner token currently grants access to all configured projects; per-human project roles are not implemented. Workspace tokens and environment variable names containing key/secret/password/auth patterns are removed from provider and check subprocess environments. AI output is sanitized for common token patterns in logs. Claude's available tools omit Bash; Codex uses the CLI workspace-write sandbox. Configured project checks still run as local commands under the laptop user's account.

The AI and project source are untrusted inputs. Prompts and provider sandboxes reduce risk, but this is not OS-level isolation. The AI subprocess shares the server's OS user and may be able to read local files such as `.env`, SQLite state, Git metadata or unrelated credentials despite environment filtering. Worktrees share repository Git metadata. An orphaned provider process may survive a worker crash; no OS job-object/process fencing has been verified. Arbitrary task text could still induce harmful file edits inside a worktree, and the regex-based secret masker is incomplete. Task approval records acceptance; it does not merge or deploy. Protected file changes mark the result unverified. This system must not receive unknown users or sensitive repositories until command confinement, lease fencing, project ACLs, secret redaction, prompt injection handling, and a security review are strengthened.

No local development port is intentionally bound to a public interface. Tailscale was not installed in the tested Windows environment, so HTTPS ingress, ACL, phone login, network interruption, and lock-screen behavior remain unverified. Do not treat this document as a passed security audit.
