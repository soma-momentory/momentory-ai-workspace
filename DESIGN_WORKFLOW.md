# Design Workflow

The shared `EXPLORE` mode asks Claude and Codex independently for distinct information hierarchy, layout, brand, accessibility, responsiveness, and implementation approaches using the current project's design rules. Both proposals and provider usage are persisted. A person chooses the candidate; a numeric score alone never approves a design.

Momentory's registered `momentory-expo-lab` adapter connects its existing Expo Lab Studio. The Lab uses shared React Native previews, named drafts, visual/property editing, JSON import/export, and Playwright device presets. The structural home hero schema also supports validated text and group blocks, add/delete/reorder/nest/unnest operations, and immediate rendering. EXPLORE asks each provider for a `studioPatch` using approved design keys. Workspace rejects unknown or invalid keys, unchanged drafts, and duplicate drafts; it converts valid patches into editable Studio JSON. A user may also upload a Studio JSON candidate.

Candidate registration returns immediately with `CAPTURE_PENDING`. The server renders in the candidate task's clean Git Worktree, records that checkout's commit as `baseHead`, and resumes pending captures after a server restart. A failed capture is `CAPTURE_FAILED` and can be retried in the UI or through `POST /api/candidates/:id/retry`; repeated dependency fetches are bounded. `test:design-cancel` aborted an active capture, and interrupted boundary probe files are removed only after checking their exact content and the absence of a live scope. The Expo Lab runs on loopback inside the WSL sandbox on Windows and is stopped after an idle interval. Workspace captures baseline and candidate screenshots at 375, 390, 402, and 430pt using equal content and settings. The home screen also includes ten-task and long-title states at 375pt with 1.5× text. Capture checks horizontal overflow, structural overlap, and text clipping. Screenshots are served only after Workspace authentication.

The user records a selection rationale, which becomes context for later exploration. Momentory blocks selection without a rendered screenshot. Selecting a rendered Studio export queues a separate isolated FE task. The Workspace validates the schema again, requires the screenshot commit to match the new task's base commit, atomically writes only `src/design/studioApproved.json` in that task's Worktree, and runs FE typecheck, lint and Jest. It does not execute candidate-supplied code or merge the resulting patch into a protected branch.

Earlier real CLI integration produced four editable drafts, two from each provider, followed by independent text evaluations. The structural editor and home/non-home web captures were verified on the FE structural branch `ba34e0d`; a fresh source-pinned selection-to-approval flow is recorded in `TEST_REPORT.md` according to its actual result. React Native iOS and Android screens, physical phone selection, and untested screens/states remain separate validation items. A numeric evaluation score never selects a design automatically.
