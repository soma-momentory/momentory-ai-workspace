# Design Workflow

The shared `EXPLORE` mode asks Claude and Codex independently for distinct information hierarchy, layout, brand, accessibility, responsiveness, and implementation approaches using the current project's design rules. Both proposals and provider usage are persisted. A person chooses the candidate; a numeric score alone never approves a design.

Momentory's registered `momentory-expo-lab` adapter connects its existing Expo Lab Studio. The Lab uses real shared React Native previews, named drafts, visual/property editing, JSON import/export, and Playwright device presets. EXPLORE now asks each provider for a `studioPatch` using the approved design keys. Workspace rejects unknown or invalid keys, unchanged drafts, and duplicate drafts; it converts valid patches into editable Studio JSON. The worker candidate API validates and captures each generated draft. A user may also upload a Studio JSON candidate. The adapter can start the Lab on localhost when it is not already running. Workspace captures baseline and candidate screenshots at 375, 390, 402, and 430pt using equal content and settings. For the home screen it also captures a ten-task state and a long-title state at 375pt, scrolling both previews to the same content position; the long-title state uses 1.5× text. It checks horizontal overflow at each capture. Screenshots are served only after Workspace authentication. The rendered candidate and raw proposal remain distinguishable in storage.

The user records a selection rationale, which becomes context for later exploration. Momentory blocks final selection of a candidate without a rendered screenshot. Selecting a rendered Studio export queues a separate isolated FE task that calls the Lab's existing `apply-design.mjs --write` inside its worktree and runs FE checks. The full pipeline test reached `AWAITING_APPROVAL` after typecheck, lint and all 1,664 Jest tests passed. No main app source was replaced.

Real CLI integration produced and rendered four editable home drafts, two from each provider, followed by independent evaluations. The existing Studio schema supports token, asset, typography, alignment and spacing changes, but not arbitrary component order or information-architecture changes. Those proposed structural changes remain text proposals requiring a separate reviewed implementation. Capture has been checked for the home screen at four widths and two additional states, without all screen/state or native device regressions. The long-title example displays an ellipsis, which requires product review. The previously timed-out selected-design source task was resumed; typecheck, lint and all 126 Jest suites/1,664 tests passed. A separate new generated-candidate pipeline also passed all three checks and awaits approval in its isolated worktree. Native iOS/Android results are separate. Design exploration remains incomplete for release until structural drafts and broader visual/device verification are implemented.
