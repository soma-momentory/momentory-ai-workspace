# Design Workflow

The shared `EXPLORE` mode asks Claude and Codex independently for distinct information hierarchy, layout, brand, accessibility, responsiveness, and implementation approaches using the current project's design rules. Both proposals and provider usage are persisted. A person chooses the candidate; a numeric score alone never approves a design.

Momentory's registered `momentory-expo-lab` adapter connects its existing Expo Lab Studio. The Lab already uses real shared React Native previews, named drafts, visual/property editing, JSON import/export, and Playwright device presets. A user may upload a Studio JSON candidate to Design Review. Workspace calls the Lab's existing export validator, then captures baseline and candidate screenshots at 375, 390, 402, and 430pt using equal content and settings. It checks horizontal overflow at each width. Screenshots are served only after Workspace authentication. The rendered candidate and raw proposal remain distinguishable in storage.

The user records a selection rationale, which becomes context for later exploration. Momentory blocks final selection of a candidate without a rendered screenshot. Selecting a rendered Studio export queues a separate isolated FE task that calls the Lab's existing `apply-design.mjs --write` inside its worktree and runs FE checks. That result still requires a second approval and does not replace the main app source automatically.

Current gaps: AI text proposals are not converted automatically into editable Studio drafts; capture has only been checked for the home screen at four widths, without all state and native device regressions. An actual selected-design source task changed the isolated FE token file and passed typecheck/lint, but the full Jest run failed in the pre-existing `bodyRelease.test.tsx` timeout (also reproduced on untouched FE), so the task remains `UNVERIFIED`. Native iOS/Android results are separate. Design exploration remains incomplete for release.
